# zenfree Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add OpenCode Zen's free-tier models to pi as auto-synced providers `zenfree` + `zenfree.res`, mirroring clinefree.

**Architecture:** Second `FreeModelSource` (`sources/opencode.ts`) behind the existing seam, with three small generalizations: state store factory, models.dev feed param, and multi-provider sync. Key-required auth; console `/api/v2/config` is lineup+capabilities+baseUrl; npm dist-tag is the client version; identity headers minted per conversation/turn; one provider per transport sharing one credential.

**Tech Stack:** TypeScript (node --experimental-strip-types), vitest, pi extension API (`registerProvider`/`streamSimple`), pi-ai compat `getApiProvider`.

**Spec:** `docs/superpowers/specs/2026-09-27-zenfree-design.md` (§ refs below are zen-§).

## Global Constraints

- Nothing may block pi startup: every network/parse path fail-soft (zen-9).
- Tests never touch the network — every fetcher injected.
- Free = model whose every `cost` tier has `input == 0`; missing `cost` ⇒ not free (zen-4).
- Provider ids: `zenfree` (openai-completions), `zenfree.res` (openai-responses) — exact strings.
- UA floor: version ≥ 1.17.0 (`opencode/latest/<ver>/cli`); baked-in fallback `opencode/latest/2.0.11/cli` (zen-3).
- Identity formats: session `ses_` + 12 lowercase-hex + 14 base62 (descending); request `msg_` + same-length ascending (zen-6).
- Runtime credential invalidation only on HTTP 401 (zen-5); 403/426/429 relay, never evict.
- Config `~/.pi/agent/zenfree.json` (0600, atomic); cache `~/.pi/agent/zenfree/cache/` (zen-7). Env: `ZENFREE_CONFIG`, `ZENFREE_CACHE`.
- Cost registered as zero for every zen model (zen-4).
- clinefree behavior, paths, and env vars unchanged (zen-7).

## Review Focus

Five behaviors no task's normal tests exercise; each pinned by the named test in its owning task.

1. **Brand-new free model in config, absent from models.dev** → config limits + zen reasoning defaults, never crash/undefined → Task 7 test "resolves a config-only model with zen defaults for unspecified fields".
2. **426 stale-UA at runtime** → error relayed, user notified, version re-check forced (next sync uses fresh UA) → Task 9 test "notifies and forces a version re-check on 426".
3. **Responses-transport model (muse-spark) must flow through zenfree.res's streamSimple with identity headers** (pi only dispatches on api match) → Task 9 test "routes a responses-api model through the responses impl with identity headers".
4. **Console flips the whole lineup to paid** → both providers unregistered, aggregate notification, switch prompt when the active model was delisted → Task 6 test "unregisters every provider and prompts a switch when the free lineup empties".
5. **models.dev payload has no `providers` wrapper** (`opencode` is top-level — same gotcha that bit clinefree live) → Task 2 test "extracts the opencode block from the wrapper-less payload".
